host and views: load content at startup, and make the catalog singular

The shell now builds a `qp::host::PluginHost`, scans `QP_PLUGIN_DIR` (or a `plugins/`
directory beside the executable), negotiates each manifest's capability bits against an
explicit grant, reports every attempt on stderr, and hands its node catalog to the window.
Statically linked content and directory-loaded content land in the same registries, which
is what makes "everything is a plugin" a property of the platform rather than of a build.

Verified end to end rather than argued: with `QP_PLUGIN_DIR` pointing at the host fixture,
the running shell printed

    mounted org.qp.fixture.host.content (...qp_fixture_host_content.dll) with 4 contributions

and its palette showed `Fixture Spinner` and `Fixture Meter` above the demonstrator types.
A dynamically loaded library's node types are in the editor a user is looking at.

The grant is written out in `main` rather than taken from `kKnownCapabilities`, and that is
a decision: a host that grants everything it knows cannot refuse anything, so "what may this
session do" would be answered by whichever plugins happened to be present.

`views::TypeCatalog` is gone. It existed because `INodeCatalog` offers no enumeration and the
editor needs one, so the enumerable container was written where the enumerating caller was --
in the consumer layer. Content plugins then made the cost visible: a plugin's main
contribution is a node type and the only enumerable catalog belonged to a layer a plugin
cannot reach. The container is now `graph::NodeTypeRegistry` (previous commit) and this
commit keeps only what is genuinely the view's: `views::by_category`, a pure function over
the registry. Two containers of the same thing would be two answers to "which types exist",
and the palette would show whichever it happened to be given.

`EditorWindow` therefore borrows the composition root instead of owning a catalog, and its
demonstrator types go through `PluginHost::add_builtin_node_type` so they are attributed
(`origin_of` answers `qp.builtin`) and removable like any other contribution -- a type that
existed without the record knowing about it is precisely the hole the record closes. The
window also stops declaring an unused `authoring::Registry`.

`host` uses `runtime::to_path` rather than repeating the char8_t conversion for a directory
scan; that function gained a public declaration in the previous commit for this caller.

GCC 656/656, MSVC 657/657; all four contract partitions and the layer gate green.

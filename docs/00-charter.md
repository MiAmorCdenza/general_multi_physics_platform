# qp 项目章程

> 本文件是全树最顶层的锚。任何模块规范、接口签名、函数契约与本文件冲突时，
> **以本文件为准**；确需修改本文件的，必须走 ADR 流程（见 §7）。

---

## 1. 产品定位

**一句话**：面向大学基础物理实验（测量为主）的本地化通用仿真平台。

**它不是什么**：不是"简化版 Comsol"。竞争对手不是仿真软件，是 **PhET + Excel 的组合**。

**差异化只有一个**：把

```
测量 → 记录 → 不确定度 → 报告
```

这条闭环做成平台的一等公民。现有工具（PhET 给现象、Excel 给表格）都不提供这条闭环。

---

## 2. 铁律（不可协商）

以下三条是全平台的公理。任何模块、插件、视图若违反，属于设计错误，不是风格问题。

### R1 —— 真值层与显示层严格分离

> 学生写进报告里的任何一个数字，**都不能直接精确地从界面上读出来**。
> 它必须来自"读数 + 不确定度"。

推论：
- 只有**仪器误差模型**能产生读数（reading）。仿真真值（truth）不得直接进入读数通道。
- 视图插件**禁止**订阅真值层，只允许订阅读数层。
- 数据通道上真值与读数必须是**两个不同的端口类型**，不能都是 `scalar`。

### R2 —— 随机性可复现

> 同一份配置 + 同一个 seed ⟹ 逐位相同的读数序列。

推论：
- 任何函数若依赖随机，必须在契约里标注 `@nondet` 并说明种子来源。
- 禁止使用未播种的 `rand()` / `std::random_device` / `time()` 作为熵源。
- seed 属于**运行身份**（见 `plan-tree.md` §L2 `runtime/`），不属于插件私有状态。

### R3 —— A 类不确定度必须来自重复测量

> 不确定度不能被"算出来"，只能被测出来。

推论：
- 平台必须支持"同一实验重复 N 次"作为一等操作。
- 单次测量不得凭空产生 A 类不确定度分量。

## 3. 课堂工程要求（同样是硬约束）

| 编号 | 要求 | 对架构的直接约束 |
|---|---|---|
| C1 | 确定性重放 | 运行身份必须记录 seed + 参数集 + 图版本 + 插件版本 |
| C2 | 永不数值爆炸 | 自适应子步 + 限幅优先于精度；内核必须提供钳制策略 |
| C3 | 时间轴与快照 | 时间轴是平台的机制，不是视图的私有状态 |
| C4 | 崩溃隔离 | 插件崩溃不得带走主进程（schema 域） |
| C5 | 投影优先 UI | 高对比、大字号、色盲安全——属于视图插件的验收项 |
| C6 | 仪器一等公民 | `IInstrument` 与 `ISimModel` 同时立项，不许后补 |
| C7 | 黄金用例回归 | 每个数值内核必须有固定输入的逐位对照用例 |
| C8 | 模型置信度面板 | 能量漂移、∇·B 漂移必须可见——数值误差不得被误认为物理 |

## 4. 架构总原则

### 4.1 四层结构

```
L0 core/        契约与机制 —— 唯一不可插件化的部分
L1 core/graph/  结构、求值、缓存、调度
L2 core/runtime/ 运行身份、数据记录、传输 ABI
L3 core/authoring/ 视图服务 —— 所有 UI 都挂在这里
```

### 4.2 地基判据

> **地基 = 让别人能接上来的东西。插件 = 接上来的东西本身。**
>
> 更可操作的一问：**它是"接口长什么样"，还是"接口背后填了什么"？**

三条推论：
1. 地基 = 契约 + 机制 + 调度 + 量纲；插件 = 内容 + 实现 + 展示。
2. 如果一个东西用户没法通过插件替换掉它，它就是地基。
3. **地基的接口面必须最小**——因为它是唯一改了要所有人重编译的部分。

### 4.3 最小化的适用对象（重要澄清）

> **「地基接口面必须最小」≠「实现可以简化」。**

| 对象 | 原则 |
|---|---|
| 接口面 / 契约 / 被冻结的部分 | **最小**——越小越稳 |
| 实现 / 内部 / 每个函数 | **零妥协**——契约完整、职责单一、必须过测试 |

技术债的真实成因不是"写得少"，而是**归属不清**：一个函数做两件事、状态有两个主人、错误没人负责。
因此本项目的核心规范目标是：**每个函数有唯一归属和唯一契约**。

### 4.4 表达完备性，而非图灵完备

> 图的形状**永远静态**。图元是纯函数，纯函数内部可以任意复杂。

- 禁止：图层面的循环、动态拓扑、可变求值顺序。
- 理由：缓存命中、静态量纲校验、停机性、可复现、可追溯——五条都依赖静态图。
- "想要任意计算"的合法出口是**脚本节点插件**（类型化输入输出、纯函数、有超时、禁止进热路径），
  不是让编辑器图灵完备。

## 5. 技术栈（已定）

| 项 | 选择 |
|---|---|
| 语言 | C++20 |
| 构建 | CMake ≥ 3.24 |
| GUI | Qt 6.5+（QML + Qt Quick 为主，QWidget 用 `QQuickWidget` 嵌入） |
| 线性代数 | Eigen |
| 测试 | **Catch2 v3**（单元/契约）+ **RapidCheck**（性质）+ **Google Benchmark**（性能红线）+ **libFuzzer**（加载器） |
| 静态检查 | **clang-tidy** + clang-format + 自定义层级依赖检查 |
| 命名空间 | `qp::` |
| 核心层目录 | `core/` |

**已否决**：Web 前端（本地效率优先；未来可作为消费者重新接入，见 ADR-0002）。
**约束**：若将来要支持 Web，非 Python 插件只能出现在烘焙（`field`）域，**永不进热路径**
（wasm 无法加载 `.pyd`/DLL，`QPluginLoader` 在 WebAssembly 下不存在）。

## 6. 平台承诺（Promise）

平台必须持续保证以下四条。它们是本项目的存在理由，不是特性列表：

1. **加一个仪器不需要改模型代码。**
2. **加一个实验 = 写一份 YAML，不需要编译。**
3. **改仪器精度，必须真的改变最终不确定度。**
4. **同 seed 重开，读数序列逐位相同。**

验收测试必须能自动证明这四条。做不到就是架构退化了。

## 7. 变更流程

| 变更类型 | 流程 |
|---|---|
| 修改本文件 §2 铁律 | 只能新增，不能删除；需 ADR + 全量回归 |
| 修改 `abi/` 下任何结构布局 | 必须升 `abi_version` + 更新 `static_assert` + 全量兼容测试 |
| 修改已冻结接口 | ADR + 影响面分析 + 所有实现方同步 |
| 新增插件接口 | 必须同时提交**契约合规套件**（见 `standards/test-taxonomy.md` §8） |
| 新增函数 | 必须有 `@tests` 条目，否则 CI 拒绝合并 |

**本文件是"法"。`plan-tree.md` 是"图"。`standards/` 是"工艺"。三者必须一致。**

build(package): add the packaging script, and make the dialect gate stateful

scripts/package.ps1 assembles a distributable directory and then proves it runs
with Qt's own bin removed from PATH. That last step is what makes the word
"distributable" mean anything: a package that only works on the machine that built
it passes every other check in the script.

The package carries what LGPL-3.0 conditions redistribution on: the Qt DLLs (so a
recipient can replace them, section 4(a)), the full LGPLv3 text, and -- for
Apache-2.0 sections 4(a) and 4(d) -- LICENSE and NOTICE. The LGPLv3 text is
deliberately not in the repository, because there is no Qt code here and
committing it would suggest otherwise; the script locates an installed copy and
fails if it cannot, rather than producing a package that looks complete.

The package must contain exactly what NOTICE declares. The first run produced a
directory holding Qt6Network.dll plus tls/ and networkinformation/ plugins, while
NOTICE declared three modules. Both files were true and they disagreed, so the
licence text a recipient reads described a different artifact from the one they
received. windeployqt works from imports: a Qt Widgets application references
Network through Qt's plugin infrastructure even when it never opens a socket.
Reconciled towards the smaller artifact rather than by widening NOTICE -- a
networking stack in a classroom physics tool with no network feature would be both
larger and a bigger licence surface for no benefit. Qt6Svg genuinely is pulled in
by the icon engine, so it was added to the declaration instead.

The dialect gate is now stateful across lines. A per-line scanner cannot tell a
PowerShell here-string's body from a comment, because the opening delimiter is on
an earlier line, so it reported D2 against the localized help text inside
Fail @"..."@ in package.ps1 -- text this project deliberately keeps in Chinese for
its users. The false positive landed on exactly the lines that are correct, and the
usual response to those is to weaken the rule, so the scanner tracks the state
instead. Two fixtures pin both directions.

Three more traps found by running it:

  - package.ps1 written without a UTF-8 BOM. Windows PowerShell 5.1 decoded it as
    ANSI and reported "The Try statement is missing its Catch or Finally block" at
    a line that is correct. gate.encoding caught it before it needed debugging.

  - ErrorActionPreference = Stop plus a native command writing to stderr is a trap:
    PowerShell 5.1 promotes that stderr into a terminating error, so windeployqt's
    warning about missing DirectX shader DLLs aborted the script after it had
    copied exactly one DLL, leaving a directory that looked like a package.

  - Start-Process -Environment is PowerShell 7 only; on the 5.1 that ships with
    Windows it fails at parameter binding, before the check runs.

GCC 15.2.0 (MinGW i686) 465/465 with views off and no Qt present; all six gates
green; the packaged directory verified to launch with Qt's bin removed from PATH.

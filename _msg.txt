test(contracts): gate the Qt-free view layer, and make --exclude coherent

The view layer's Qt-free half has contract blocks of its own and they were not
being checked, because the existing gate's header root is core/. Wiring them in
needed two things.

First, a test root holding exactly their cases. The gate judges in both
directions -- every @tests id must exist, and every TEST_CASE must be claimed --
so two invocations must see **disjoint** sets of test cases. Any directory in both
scopes makes the other invocation's legitimate cases look like orphans. The model
tests therefore move from tests/unit/views/ to tests/model/, which gives the second
invocation a root of its own.

Second, `--exclude` had to become coherent. It filtered the orphan count but NOT
the scan of module-level contract blocks in test files, so a subtree handed to
another invocation kept reading its own module contracts and claiming cases this
one cannot see -- reporting them as unsatisfied references. That is a real defect,
found by the second gate complaining about `fp.*`, whose cases belong to the first
gate's root. Both loops now apply the same filter.

The exclude term matches either a directory name anywhere in the path (`views`) or
a path fragment (`unit/views`). The fragment form exists because the name form
cannot tell `tests/unit/views` from `tests/unit/units`: both contain a segment
starting with "unit", and the first attempt at this excluded the wrong one.

Result: gate.contracts scans core/ (271 contracts) and gate.contracts.views scans
views/model (10 contracts), each with a test root the other cannot see. GCC 15.2.0
(MinGW i686) 465/465 with views off and no Qt present.
